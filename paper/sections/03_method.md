## 3. Method

**Task.** Given a bug report and the repository at the base commit, the agent must name the files and the functions or methods that the fix modifies. We study localization, not patch generation. It isolates how an agent navigates a codebase and needs no containerized test execution. Tasks come from SWE-bench Verified [TODO cite]. Gold locations are the innermost function or class touched by each changed line of the reference patch, or the file when no finer node exists.

**Agent.** All arms use one tool-calling loop capped at 30 steps. Tool output is truncated at 6,000 characters and the bug report at 12,000. The base tools are `list_dir`, `view_file` (numbered lines, 200-line default window), `search_text` (regular expression over text files, up to 50 matches) and `submit`, which takes files and functions written as `path::Class.method`. Arms share prompts apart from the additions below, and share sampling settings and the serving stack [TODO: temperature, serving software and versions, model checkpoints].

**Code graph.** We build the graph with Python's `ast` module. Nodes are files, classes and functions, including methods and nested functions. Edges are `contains`, `imports`, `inherits` and `calls`. A call becomes an edge only when it is statically resolvable: a name defined or imported from the repository, a `self` or `cls` method (searched through resolved base classes), a module alias, or a class instantiation. Method calls on objects of unknown type stay unresolved. Across the surveyed repositories, 28% of resolvable calls become edges [TODO: final figure, per repository]. The graph is therefore incomplete by construction, and we treat its quality as a threat to validity.

**Graph tool.** `graph_neighbors(symbol, direction, hops)` returns the symbols connected to a symbol within one to three hops, labeled caller, callee, imports, imported_by, base_class, subclass, member or container. A name that matches several symbols returns the candidates.

**Arms.** A1 has the base tools. A2 adds `graph_neighbors`. A3 is A2 plus a one-sentence reminder at the end of the prompt. A4 is A2 with the first model turn forced to call `graph_neighbors`. A5 has no graph tool, and the prompt includes the one-hop neighborhoods of up to five anchor symbols. A6 is A2 on a graph whose calls, imports and inheritance edges are rewired at random while every node keeps its in-degree and out-degree. A6 tests whether any benefit comes from real structure or only from receiving extra text.

**Strata.** To ask when structure helps, we measure how far the fix lies from what the report mentions. Anchors are code symbols and file paths in the report that resolve to exactly one repository symbol. Backticked names count, and so do plain names that look like code. Symbols in test, documentation and example directories do not count. Hop distance is the shortest undirected path between any anchor and any gold location over all edge kinds. Tasks are near (0 to 1 hops), far (2 or more) or without an anchor. Of 358 surveyed tasks, 163 were near, 108 far and 87 had no anchor [TODO: final counts after the audit]. We checked anchor correctness by a blind audit of 30 tasks, 20 far and 10 near [TODO: audit result].

**Metrics.** Adoption is the share of runs with at least one `graph_neighbors` call. Localization is file recall and function recall against the gold locations, in an exact form and a lenient form that also credits a class for one of its methods, plus function precision. We also record steps and tokens. Intervals are Wilson intervals, and arms are compared within tasks [TODO: statistical model].
